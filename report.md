# Отчёт

## 1. Подготовка окружения

### Суть этапа

В начале устанавливаются версии библиотек, с которыми рассчитан ноутбук. Фиксируется `seed=42`, после чего выбирается устройство для вычислений. Это нужно, чтобы повторный запуск давал ту же выборку и те же случайные baseline-векторы.

### Что реализовано

- Устанавливаются `datasets`, `soundfile`, `librosa`, `transformers`, `torch`, `scikit-learn`, `umap-learn`, `pandas`, `numpy`, `matplotlib` и `seaborn`.
- Фиксируется случайность для `random`, `numpy` и `torch`.
- Выводятся версии Python и основных библиотек.
- В константах хранятся идентификаторы и ревизии датасета, метаданных и CLAP.

### Результат этапа

После выполнения ячейки определены все зависимости и параметры, которые используются дальше: размер выборки, ограничения на артистов и альбомы, длина аудиофрагмента и размер батча CLAP.

## 2. Чтение данных

### Суть этапа

Треки берутся из `vtsouval/mtg_jamendo_autotagging`. Датасет открывается в streaming-режиме, поэтому для выбора треков не требуется скачивать весь набор аудио.

### Что реализовано

- `load_dataset` открывает поток метаданных.
- Читаются `track_id`, `artist_id`, `album_id`, длительность, жанры, инструменты и mood/theme.
- `parse_labels` преобразует строковые представления списков в обычные Python-списки.
- Метки приводятся к нижнему регистру, пустые значения и повторы удаляются.
- Проверяется наличие нужных полей и корректность идентификаторов и длительности.

### Проверка аудио

Перед сбором выборки декодируются два трека. Для каждого проверяется:

- один аудиоканал;
- частота дискретизации 16 кГц;
- длительность от 29 до 31 секунды;
- отсутствие `NaN` и бесконечных значений.

`waveform` содержит значения звукового сигнала, а `sample_rate` показывает, сколько таких значений приходится на одну секунду. Аудио декодируется через `soundfile` и на этом этапе хранится в оперативной памяти.

### Результат этапа

Подтверждается, что структура датасета и формат аудио подходят для дальнейшей обработки.

## 3. Формирование выборки

### Суть этапа

Из исходного датасета выбираются 100 треков. Выборка должна содержать разные жанры и не состоять из большого количества треков одного исполнителя.

### Что реализовано

- Из потока метаданных берётся пул из 4000 строк.
- Пул перемешивается с `seed=42`.
- Для каждого трека проверяются идентификаторы, длительность и списки меток.
- Некорректные строки пропускаются и учитываются в счётчике `rejected_rows`.
- Для каждого жанра заранее считается количество доступных треков, исполнителей и альбомов.

В выборке действуют ограничения:

- ровно 100 треков;
- не больше двух треков одного исполнителя;
- не больше одного трека из одного альбома;
- не меньше пяти треков для каждого из десяти основных жанров.

Основные жанры: rock, pop, electronic, jazz, classical, folk, hiphop, metal, reggae и blues.

### Функция `add_row`

Функция получает строку метаданных и добавляет её в выборку, если трек ещё не выбран и ограничения по исполнителю и альбому не нарушены. Одновременно обновляются счётчики треков, артистов, альбомов и жанров.

Сначала функция набирает недостающие жанровые квоты. После выполнения квот оставшиеся места заполняются другими подходящими треками.

### Результат этапа

Создаётся `manifest_df` — таблица из 100 выбранных треков с исходными тегами и информацией о способе отбора.

## 4. Добавление официальных метаданных

### Суть этапа

В Hugging Face-версии датасета нет всех полей, которые нужны для итоговой таблицы. Название трека, имя исполнителя, ссылка и лицензия добавляются из официальных файлов MTG-Jamendo.

### Что реализовано

- `raw.meta.tsv` читается через `pandas.read_csv`.
- Числовой `track_id` извлекается из официального строкового идентификатора.
- Поля переименовываются в `track_title`, `artist_name`, `album_name`, `release_date` и `track_url`.
- `audio_licenses.txt` разбирается регулярными выражениями.
- Для каждого `track_id` находится ссылка на лицензию Creative Commons.
- Официальные данные объединяются с `manifest_df` по `track_id`.

### Результат этапа

Создаётся `playlist_manifest.csv`. Это паспорт выборки: в нём записано, какие треки используются, откуда они получены, какие исходные теги имеют и по какой лицензии доступны.

## 5. Загрузка выбранного аудио

### Суть этапа

После формирования списка загружается аудио только для выбранных 100 `track_id`. Остальная часть аудиодатасета не обрабатывается.

### Что реализовано

- В `load_dataset` передаётся фильтр по выбранным `track_id`.
- Каждый аудиофайл читается через `soundfile` как массив `float32`.
- Повторно проверяются число каналов, частота дискретизации, длительность и конечность значений.
- Аудио сохраняется в словарь `audio_by_track` в виде пары `(waveform, sample_rate)`.
- Проверяется, что аудио найдено для всех 100 треков.

### Результат этапа

В оперативной памяти находится звук для всей выборки. Отдельные MP3-файлы кодом в папку проекта не записываются.

## 6. Акустические признаки

### Суть этапа

Для каждого трека рассчитываются простые численные характеристики звука. Они используются как интерпретируемый baseline, с которым затем сравнивается CLAP.

### Функция `extract_acoustic_features`

Функция принимает `waveform` и `sample_rate`. Перед расчётом она проверяет размерность сигнала, длину, тип данных, частоту дискретизации и отсутствие некорректных значений.

Из сигнала извлекаются:

- `tempo_bpm` — оценка темпа;
- `rms_mean` и `rms_std` — средняя энергия и её изменение;
- `zcr_mean` — частота пересечения сигналом нуля;
- `spectral_centroid_mean` — положение центра спектра;
- `spectral_rolloff_mean` — частота, ниже которой находится основная часть энергии;
- `chroma_entropy` — равномерность распределения энергии по 12 нотным классам;
- `is_silent` — признак тишины;
- `tempo_reliable` — достаточность атак для оценки темпа;
- среднее и стандартное отклонение для 13 MFCC.

Всего для одного трека получается 35 акустических признаков.

### Проверка функции

Функция запускается на четырёх типах входов:

- тишина;
- синусоида 440 Гц;
- клики с темпом 120 BPM;
- некорректные массивы и sample rate.

Проверяется обнаружение тишины, спектральный центр синусоиды, оценка темпа и обработка ошибок.

### Результат этапа

Для всех треков создаётся `acoustic_df`. Затем он объединяется с `manifest_df` в таблицу `track_df`.

## 7. CLAP-эмбеддинги

### Суть этапа

Акустические признаки описывают форму сигнала, но не полностью отражают музыкальный смысл. CLAP помещает аудио и текст в одно векторное пространство, поэтому его эмбеддинги можно использовать для семантического поиска.

### Подготовка аудио

Функция `make_clap_segments` выполняет три действия:

1. Ресемплирует трек с 16 до 48 кГц.
2. Обрезает или дополняет сигнал до 30 секунд.
3. Делит его на три фрагмента по 10 секунд.

Три фрагмента позволяют учитывать начало, середину и конец доступной записи.

### Получение эмбеддинга

- Используется `laion/clap-htsat-fused` с зафиксированной ревизией.
- `ClapProcessor` преобразует аудиофрагменты в формат модели.
- `ClapModel.get_audio_features` строит эмбеддинг каждого фрагмента.
- Эмбеддинги нормализуются.
- Три вектора одного трека усредняются.
- Итоговый вектор снова нормализуется.

Нормализация позволяет напрямую использовать скалярное произведение как cosine similarity.

После расчёта проверяется медианное сходство между разными треками. Если оно выше `0.95`, выполнение останавливается: такие эмбеддинги почти не различают записи.

### Результат этапа

Создаётся матрица `clap_embeddings`: одна строка соответствует одному треку. Проверяются количество строк, отсутствие `NaN` и норма каждого вектора.

## 8. Zero-shot признаки

### Суть этапа

Кроме полного эмбеддинга, для каждого трека назначаются понятные человеку текстовые признаки. Для этого аудио сравнивается с заранее заданными текстовыми описаниями.

Используются четыре группы:

- genre — музыкальный стиль;
- mood — эмоциональное состояние;
- context — ситуация прослушивания;
- atmosphere — общий характер звучания.

Genre помогает искать музыку похожего стиля, mood — треки с близким настроением, context — музыку для одной ситуации, atmosphere — композиции с похожим общим звучанием.

### Функция `zero_shot_scores`

Для каждого класса строятся три коротких текста по общим шаблонам. Например, жанр описывается как `A rock music track`, `Music in the rock genre` и `A recording with a typical rock sound`. Для mood, context и atmosphere используются свои наборы шаблонов.

CLAP строит эмбеддинг каждого текста. Три вектора одного класса усредняются и нормализуются, образуя class prototype. Аудио сравнивается уже с прототипами классов. Такой prompt ensemble меньше зависит от одной формулировки и позволяет добавлять новую метку без отдельного ручного описания.

У жанров из каждого столбца scores вычитается его среднее значение по выборке. Такая калибровка убирает общий перекос модели в сторону отдельных жанров и не использует исходную разметку треков.

Для каждой группы сохраняются:

- `*_pred` — метка с наибольшим score после калибровки жанров;
- `*_score` — сходство с выбранной меткой;
- `*_margin` — разница между первым и вторым вариантом, для жанров после калибровки.

`score` не является вероятностью. `margin` используется только как относительный показатель однозначности выбора.

Для каждой группы также проверяется число разных предсказаний. Если все треки получили одну метку, пайплайн останавливается и не сохраняет такой результат как готовый датасет.

### Выбор подхода

Готовый аудиоклассификатор проще использовать, но он ограничен набором классов, на которых обучался. LLM по названию и исполнителю не анализирует сам звук. Ручная разметка позволяет точнее задать нужные категории, но требует нескольких разметчиков и проверки согласованности. CLAP выбран потому, что позволяет менять текстовые признаки без переобучения модели.

### Результат этапа

Метаданные, акустические признаки и zero-shot признаки объединяются в `enriched_df`. Таблица сохраняется в `enriched_tracks.csv`, а эмбеддинги и соответствующие `track_id` — в `clap_embeddings.npz`.

Фактический `genre hit@1` и распределение предсказаний выводятся в ноутбуке после пересчёта class prototypes. Предсказания дополнительно проверяются на коллапс в один класс.

## 9. Разведочный анализ

### Суть этапа

EDA используется для проверки состава выборки и поведения рассчитанных признаков до экспериментов с похожестью.

### Что анализируется

- Распределение исходных жанров после `explode` multilabel-столбца.
- Распределение предсказанных mood.
- Распределение предсказанных context.
- Распределение надёжных значений tempo.
- Распределение RMS и spectral centroid.
- Корреляции Спирмена между основными численными признаками.
- Таблица совместных значений mood и context.

Для genre дополнительно считается `hit@1`: предсказание считается правильным, если выбранный CLAP-жанр присутствует среди исходных жанров трека.

### Результат этапа

Графики показывают баланс категорий, диапазоны акустических признаков и частые сочетания zero-shot меток. Таблица `zero_shot_summary` содержит `genre hit@1` и средние значения margin.

## 10. Поиск похожих треков

### Суть этапа

Проверяется, какие представления лучше находят треки с общими исходными тегами. Сравниваются CLAP, акустические признаки и случайный baseline.

### Подготовка представлений

- Акустические признаки стандартизируются через `StandardScaler`, чтобы признаки с большими числовыми значениями не доминировали.
- После стандартизации акустические векторы нормализуются.
- CLAP-векторы уже нормализованы после получения.
- Случайные векторы генерируются с `seed=42` и также нормализуются.
- Для каждого представления строится матрица cosine similarity.

### Функция `nearest_neighbors`

Функция получает матрицу похожести, индекс исходного трека и число соседей. Она сортирует кандидатов по убыванию similarity, исключает сам трек и треки того же исполнителя, после чего возвращает нужное количество соседей.

Исключение одного исполнителя уменьшает утечку: без него метод мог бы получать высокий результат за счёт очень похожих записей одного автора.

### Метрики

`label_jaccard` считает отношение размера пересечения двух наборов тегов к размеру их объединения.

Метрики считаются на четырёх глубинах: `K = 3`, `5`, `10` и `15`. Для жанров, инструментов и mood/theme рассчитываются:

- `HitRate@K` — доля запросов хотя бы с одним релевантным соседом;
- `Precision@K` — доля соседей с общим тегом;
- `Recall@K` — доля найденных релевантных кандидатов;
- `MAP@K` — средняя точность с учётом позиций релевантных соседей;
- `MRR@K` — позиция первого релевантного соседа;
- `nDCG@K` — качество порядка с Jaccard в роли graded relevance;
- `mean Jaccard@K` — средняя степень пересечения исходных тегов.

Метрики считаются одинаково для CLAP, акустического и случайного представлений.

В таблице ниже оставлены значения предыдущего запуска для `@3`, `@5` и `@10`. Столбец `@15` появится в `retrieval_metrics.csv` после следующего запуска ноутбука.

| Представление | nDCG@3 | nDCG@5 | nDCG@10 |
|---|---:|---:|---:|
| CLAP | 0.262 | 0.291 | 0.330 |
| Acoustic | 0.211 | 0.212 | 0.240 |
| Random | 0.104 | 0.119 | 0.157 |

### Примеры

Для четырёх запросов выводятся пять соседей, их исполнители, названия, cosine similarity и исходные жанры. Для одного запроса дополнительно создаются аудиоплееры исходного трека и двух ближайших соседей.

### Результат этапа

`metrics_df` содержит 36 строк: три представления, три пространства меток и четыре значения K. Полная таблица сохраняется в `retrieval_metrics.csv`.

## 11. Визуализация эмбеддингов

### Суть этапа

UMAP используется для отображения многомерных CLAP-векторов на плоскости.

### Что реализовано

- Для UMAP используется cosine distance.
- `random_state=42` фиксирует результат.
- Каждый трек преобразуется в две координаты.
- Точки окрашиваются по одному из исходных основных жанров.

### Результат этапа

Проекция позволяет визуально посмотреть, находятся ли треки одинаковых жанров рядом. UMAP не сохраняет все исходные расстояния, поэтому отдельные группы на графике не считаются самостоятельным доказательством качества.

## 12. Проверки пайплайна

Для ошибок внешних данных используется `ValueError`. Так проверяются неправильные идентификаторы, отсутствие полей, формат аудио, пропущенные записи и невозможность собрать выборку.

`assert` используется для внутренних инвариантов и тестовых примеров:

- размер выборки равен 100;
- идентификаторы треков уникальны;
- ограничения по артистам и альбомам выполнены;
- жанровые квоты набраны;
- акустические признаки конечны;
- CLAP-эмбеддинги имеют нужное число строк и единичную норму;
- метрики находятся в диапазоне от 0 до 1;
- UMAP возвращает 100 двумерных точек;
- среди соседей нет самого запроса и повторов.

## 13. Итоговые файлы

### `playlist_manifest.csv`

Содержит исходную выборку: идентификаторы, названия, исполнителей, альбомы, ссылки, лицензии, исходные теги и параметры отбора.

### `enriched_tracks.csv`

Основной итоговый датасет. Содержит исходные метаданные, 35 акустических признаков и zero-shot признаки genre, mood, context и atmosphere.

### `clap_embeddings.npz`

Содержит два массива: `track_id` и матрицу CLAP-эмбеддингов. Файл используется для повторного поиска соседей, UMAP и других экспериментов без повторного запуска модели.

### `retrieval_metrics.csv`

Содержит HitRate, Precision, Recall, MAP, MRR, nDCG и mean Jaccard для `K = 3`, `5`, `10` по жанрам, инструментам и mood/theme.

## 14. Ограничения

- Исходные теги MTG-Jamendo неполные и могут не содержать все подходящие характеристики трека.
- Отсутствие общего тега не обязательно означает, что два трека непохожи на слух.
- Выборка состоит из 100 объектов, поэтому результаты нельзя считать полноценным benchmark.
- Значения CLAP cosine score не являются вероятностями.
- Результат zero-shot классификации зависит от выбранных формулировок текстовых запросов.
- UMAP изменяет расстояния при переходе к двум измерениям.
- Для окончательной оценки музыкальных рекомендаций нужна пользовательская проверка соседей.
